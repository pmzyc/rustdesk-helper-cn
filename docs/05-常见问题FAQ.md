# 05 · 常见问题 FAQ

> 每条按「**现象 → 原因 → 解决**」组织。RustDesk 一键配置助手只是 RustDesk 的外挂面板，不含远程控制本身；配置与网络前提见 [`01-功能说明.md`](01-功能说明.md)、[`03-局域网使用说明.md`](03-局域网使用说明.md)、[`04-EasyTier纯TCP中继服务器说明.md`](04-EasyTier纯TCP中继服务器说明.md)。

---

## Q1. 点【停止】后再点【启动】没反应 / 状态不刷新

- **现象**：点【停止】后，客户端状态仍显示「运行中」，按钮也不变回【启动】；再点【启动】好像没效果，状态迟迟不更新。
- **原因**：早先版本把服务 `RustDesk` 自动拉起的 `--server` 子进程也当成了「客户端进程」。`--server` 结束会**立刻重生**，于是状态看起来永远「运行中」，启停按钮也就失灵了。
- **解决**：
  1. 升级到 **v5.1**（已修复：只统计真正的客户端进程，`--server` / `--service` 不再计入）。
  2. 修复后，【停止】只结束 `--tray` 客户端进程（不动服务、不影响「与服务器的连接」），状态与按钮随之更新。
  3. 若仍异常，用面板【查看日志】看 `helper.log` 记录。

## Q2. 固定密码设置后对方仍连不上

- **现象**：在面板里设置了固定密码并提示成功，但对端用它连接时仍失败，或密码似乎没生效。
- **原因**：**绝不能**把 `password` 写进 `RustDesk.toml` 的 `[options]` 段——RustDesk **不识别**这种写法。这正是「固定密码不生效」的常见原因（旧版曾这么干）。
- **解决**：
  1. 用 **v5.1**：固定密码改为调用官方命令 `rustdesk.exe --password "xxx"` 写入客户端，**立即生效、无需重启**。
  2. v5.1 还会**自动清理**配置里遗留的无效 `password` 项；也可手动检查 `%APPDATA%\RustDesk\config\RustDesk.toml` 的 `[options]` 段里没有 `password=`。
  3. 确认对端用的是**固定密码**（而非临时密码），并注意大小写与前后不要有空格。

## Q3. 客户端状态一直显示「运行中」

- **现象**：明明没看到桌面上的 RustDesk 窗口，面板却一直显示「客户端进程 ● 运行中」。
- **原因**：同 Q1——把服务拉起的 `--server` 子进程**误判**成了客户端进程（它一直由服务自动拉起，所以一直「在跑」）。
- **解决**：
  1. 升级到 **v5.1**（已修正判断口径）。
  2. 理解两者区别：**「客户端进程」= `rustdesk.exe --tray` 托盘/前台进程**；**服务 `RustDesk` 的 `--server` 是另一回事**。服务在跑不代表客户端进程在跑。
  3. 需要时用面板【启动】显式拉起客户端进程。

## Q4. 开机自启动显示「未设置」，或设置后不生效

- **现象**：勾选了自启、点了【保存】，但界面上某项仍显示 `✗ 未设置`；或重启后确实没自启。
- **原因**：
  - 「**开机即启动**」计划任务以 `SYSTEM` 身份运行，**需要管理员权限**，非管理员会建立失败；
  - 计划任务可能被系统策略/安全软件**禁用**，或保存了但未真正生效；
  - 历史版本可能存在「界面提示成功、实际没建上」的情况。
- **解决**：
  1. 右键 → **以管理员身份运行**本工具（左下角应显示「当前以管理员身份运行」）。
  2. 保存后 v5.1 会按计划任务的**真实存在情况**回刷复选框与 `✓/✗`；显示 `✗` 就是真的没建上。
  3. 手动确认：`taskschd.msc` 计划任务库里查 `RustDeskHelper`（登录后启动）与 `RustDeskHelper-Boot`（开机即启动）；被禁用就右键启用。
  4. 安全软件拦截 `schtasks.exe` 时加白名单。

## Q5. 「服务器密钥」一直红色「未确认」

- **现象**：填好服务器并【同步到客户端】【修复连接】后，底部状态行的「服务器密钥」仍是红色 `未确认`，顶部也一直 `注册中…`。
- **原因**（按概率排查）：
  1. **Key 与服务端 `id_ed25519.pub` 内容不一致**（多空格、换行、大小写错）；
  2. **服务器地址不通**（地址填错、服务端没起、虚拟网没通）；
  3. **防火墙 / 安全组** 未放行 `21116` 等端口；
  4. UDP 被封却**没有**改成走 TCP。
- **解决**：
  1. 逐字比对 Key 与 `id_ed25519.pub`。
  2. `ping 服务端地址`；`Test-NetConnection 服务端地址 -Port 21116` 看是否为 `True`。
  3. 放行端口（`21115`~`21119`，视部署含 `21116/UDP`）。
  4. 上行 UDP 被封时，在配置里让客户端**强制走 TCP**（`disable-udp`）。
  5. 都确认后点【修复连接】重置注册状态并重写配置。

## Q6. 服务器设置页留空时的行为

- **现象**：没填服务器就直接点【修复连接】（或【同步到客户端】），会发生什么？
- **原因 / 说明**：本工具**不内置任何服务器地址**（公开版把地址、Key、API 全留空）。
- **解决**：
  - 留空时点【修复连接】会被**拦下并提示**「请先切到【服务器设置】填写你自己的 ID 服务器与 Key」，不会写坏配置。
  - 正确姿势：先在【服务器设置】填 **ID 服务器 + Key**（中继服务器留空则等同 ID 服务器），再【同步到客户端】→【修复连接】。

## Q7. 停在 Windows 登录界面无法被远程

- **现象**：机器开机后停在登录界面（没人登录桌面），此时从外部无法远程到这台机器。
- **原因**：官方客户端的普通（`--tray`）进程只有在**有人登录桌面**后才会以能接收连接的形态运行；停在登录界面时它还没跑起来，自然无法被控。
- **解决**：
  - 让 RustDesk **以服务方式常驻**：Windows 服务 `RustDesk`（其 `--server` 子进程由服务自动拉起）会在系统启动早期运行，**不依赖桌面登录**。
  - 配合本助手的**开机即启动**计划任务（`RustDeskHelper-Boot`）把助手也尽早拉起，做到「开机即可远程」。
  - 注意：这是**服务**层面的事，与「客户端进程（`--tray`）」是两条独立状态。详见 [`04-EasyTier纯TCP中继服务器说明.md`](04-EasyTier纯TCP中继服务器说明.md) 第 5 节。

## Q8. Windows Defender / 杀毒软件报毒

- **现象**：首次运行或下载安装时，Windows Defender / 第三方杀软提示「未知发布者」「疑似风险」甚至直接拦截。
- **原因**：本工具是**未签名**的程序，且会在需要时**联网下载安装包**——这两点常被启发式引擎判为可疑，属**误报**。
- **解决**：
  1. 添加**白名单 / 排除项**（对本工具的 exe——Release 下载时文件名为 `RustDesk-Helper-v5.1.exe`，本地编译则输出 `RustDesk 一键配置助手.exe`——以及 `rustdesk.exe`）。
  2. 聪明选择来源：只从**本仓库 Releases** 下载二进制，核对来源可信后再运行。
  3. 想更放心就**自己编译**（见 [`02-编译打包说明.md`](02-编译打包说明.md)），从源码构建的产物你自己可控。

## Q9. 打开工具提示「未检测到已安装的 RustDesk」

- **现象**：启动助手后弹窗说未检测到已安装的 RustDesk，询问是否自动安装。
- **原因**：本机没有安装（或未被能找到的路径/注册表项匹配到）官方 RustDesk。
- **解决（自动安装流程）**：
  1. 弹窗选择「是」→ 工具通过 **GitHub API** 取最新 `x86_64` 安装包地址；
  2. **带进度窗口下载**到临时目录；
  3. 以 **`--silent-install` 提权静默安装**（会弹出「用户账户控制」，请选「是」）；
  4. 安装期间工具**最长轮询 4 分钟**等待安装完成，检测到客户端即视为成功并自动接管。
  5. 若下载失败（网络问题），工具会提示可**手动下载安装**：`https://github.com/rustdesk/rustdesk/releases/latest`。

## Q10. 日志在哪看

- **现象**：出问题想取证，但不知道日志在哪。
- **位置**：
  - **界面入口**：连接状态页的【**查看日志**】按钮；
  - **文件路径**：`%LOCALAPPDATA%\RustDeskHelper\helper.log`
    - 例如 `C:\Users\你的用户名\AppData\Local\RustDeskHelper\helper.log`。
- **解决 / 建议**：复现问题时先点【查看日志】，把相关时间段的记录提供给排查；日志里通常包含配置写入、注册状态、启停与安装等关键动作。
  - 同目录下还会存放固定密码相关的辅助文件（如 `fixed-password.txt`、`fixed-password.applied.txt`），属正常现象。
