# 03 · 局域网使用说明

> 本文说明如何在本工具配套的场景里，把 RustDesk 客户端正确地指向自建服务端，并让「服务器密钥」变成绿色「已确认（已注册）」。
> 直接起因（运营商封上行 UDP / 443 → 自建 EasyTier 纯 TCP 中继 → 补上官方缺失的开机自启等）见 [`01-功能说明.md`](01-功能说明.md)；跨地区组网细节见 [`04-EasyTier纯TCP中继服务器说明.md`](04-EasyTier纯TCP中继服务器说明.md)。

---

## 1. 两种部署场景

### 场景 A · 纯局域网自建 RustDesk 服务端

适用于**同一局域网内**（同一交换机 / 同一 Wi-Fi）多台机器互控。

- 在一台常开的机器（或 NAS、小主机）上部署 RustDesk 服务端 **`hbbs`（ID 服务器）** 与 **`hbbr`（中继服务器）**。
- 所有客户端填写**同一个 ID 服务器地址与同一个 Key**。
- **Key 必须与服务端 `id_ed25519.pub` 文件内容完全一致**——差一个字符都会导致永远注册不上。
- 服务端地址用局域网 IP，例如 `192.168.1.10`；若做了内网域名解析，也可以填 `你的域名`。

### 场景 B · EasyTier 虚拟局域网

适用于**跨地区 / 跨网络**（不在同一物理局域网）的多台机器。

- 用 EasyTier 这些机器拉进同一个虚拟局域网（自定虚拟 IP 网段，例如 `10.0.0.0/24`），虚拟网内各机器可互相 `ping` 通。
- RustDesk 服务端（`hbbs` / `hbbr`）部署在虚拟网内某台机器上，客户端把 ID 服务器 / 中继服务器都指向它的**虚拟 IP**（例如 `10.0.0.1`）。
- 完整做法与拓扑图见 [`04-EasyTier纯TCP中继服务器说明.md`](04-EasyTier纯TCP中继服务器说明.md)。

> 无论 A / B，客户端侧的填写动作完全一致（见第 4 节）。

## 2. 端口清单与放行建议

RustDesk 自建服务端涉及以下端口：

### `hbbs`（ID 服务器）

| 端口 | 协议 | 用途 |
| --- | --- | --- |
| `21115/TCP` | TCP | NAT 类型测试 |
| `21116/TCP` | TCP | ID 注册与心跳（**核心**） |
| `21116/UDP` | UDP | ID 注册与心跳（**核心**，UDP 版） |
| `21118/TCP` | TCP | 直连 / WebSocket |

### `hbbr`（中继服务器）

| 端口 | 协议 | 用途 |
| --- | --- | --- |
| `21117/TCP` | TCP | 中继转发（**核心**） |
| `21119/TCP` | TCP | WebSocket 中继 |

### 放行建议

- 常规情况：把上表端口在服务端所在机器的**防火墙**（以及路由器的端口转发，如果是公网部署）全部放行。
- **若上行 UDP 被封**（本工具作者遇到的情况）：`21116/UDP` 走不通，就改为**只走 TCP**——即 `21115` / `21116` / `21117` / `21118`。此时请在服务端/客户端上让 UDP 相关流量降级为 TCP（本工具会在配置里写入 `disable-udp`，见第 3 节）。

## 3. 局域网/自建服务端建议的配置字段

本工具的一键写入会往 `%APPDATA%\RustDesk\config\RustDesk.toml` 与 `RustDesk2.toml` 写入以下字段。它们的含义与开关时机如下：

| 字段 | 含义 | 什么时候开 |
| --- | --- | --- |
| `custom-rendezvous-server` | 你的 **ID 服务器（hbbs）** 地址 | 始终必填（填 `192.168.1.10` 或 `你的域名`） |
| `relay-server` | 你的 **中继服务器（hbbr）** 地址 | 与 ID 服务器同机时留空即可（等同 ID 服务器地址） |
| `key` | 服务端公钥，须与 `id_ed25519.pub` 完全一致 | 始终必填 |
| `disable-udp` | 禁用 UDP，**强制走 TCP** | **上行 UDP 被封**时必须开（`Y`）；UDP 可用时不必强制 |
| `allow-websocket` | 允许 WebSocket 方式连接 | 网络只放行了 TCP 且走代理/网关时可开（`Y`） |
| `enable-lan-discovery` | 局域网自动发现 | 纯同一局域网、想让客户端自动发现彼此时可开（`Y`）；跨网/虚拟网不需要 |
| `direct-access-port` | 直连端口，默认 `21118` | 使用直连/WebSocket 直连时按服务端设置填，通常 `21118` |

> 本工具默认写入的值（源码现状）：`disable-udp=N`、`allow-websocket=N`、`enable-lan-discovery=N`、`direct-access-port=21118`；`custom-rendezvous-server` / `relay-server` / `key` 用你在界面里填的值。**按你的网络实际情况决定是否把前三项改为 `Y`。**

## 4. 客户端侧操作步骤（照做即可）

在**每一台**需要被控/发起控制的机器上：

1. 打开 **RustDesk 一键配置助手**。
2. 切到 **【服务器设置】** 页，填写：
   - **ID 服务器**：`192.168.1.10`（或你的 `你的域名` / 虚拟 IP `10.0.0.1`）；
   - **中继服务器**：`192.168.1.10`（与 ID 服务器同机时也可留空）；
   - **Key**：粘贴服务端 `id_ed25519.pub` 里的内容（**逐字一致**）。
3. 点 **【同步到客户端】** —— 把上述字段写入 `RustDesk.toml` / `RustDesk2.toml`。
4. 点 **【修复连接】** —— 备份配置 → 重置 `key_confirmed` 注册状态 → 重写配置 → 重启客户端 → 后台轮询校验。
5. 回到 **【连接状态】** 页，看**底部状态行**：
   - 当 `服务器密钥：` 变成**绿色**的「**已确认（已注册）**」，说明注册成功；
   - 顶部状态胶囊也会从 `注册中…` 变为 `已连接 <服务器>`。
6. 之后即可在另一台机器上用本机 ID + 固定密码/临时密码发起远程。

> 若第 5 步迟迟不变绿，按第 6 节的失败现象逐项排查。

## 5. 防火墙 / 安全软件

- **客户端机器**：放行 `rustdesk.exe`（允许其出入站）。
- **服务端机器**：放行 `hbbs` / `hbbr` 进程，并放行第 2 节列出的端口（TCP `21115`~`21119`，视部署情况含 `21116/UDP`）。
- 第三方安全软件（火绒、360、卡巴斯基等）可能拦截 `rustdesk.exe` 的联网或 `hbbs`/`hbbr` 的监听，需要**加白名单**。
- 若服务端在公网云主机：除本机防火墙外，别忘了**安全组**放行相同端口。

## 6. 常见失败现象与排查顺序

建议**从下往上、逐项确认**，不要一上来就怀疑 Key：

1. **服务端是否真的在跑？**
   - 在服务端机器上确认 `hbbs` / `hbbr` 进程存在、端口在监听（`netstat -ano | findstr 2111`）。
2. **网络是否能到服务端？**
   - `ping 192.168.1.10`（或虚拟 IP `10.0.0.1`）通不通。
   - `Test-NetConnection 192.168.1.10 -Port 21116`（PowerShell）看 `TcpTestSucceeded` 是否为 `True`。
3. **端口 / 防火墙是否放行？**
   - 见第 2、5 节；UDP 被封时确认已走 TCP（`disable-udp`）。
4. **客户端填的地址对不对？**
   - 是否漏填、是否把 ID 服务器与中继服务器填反、是否带了多余的 `http://` 前缀（应填纯 `主机` 或 `主机:端口`，按服务端实际部署）。
5. **Key 是否与 `id_ed25519.pub` 完全一致？**
   - 有没有多一个空格、换行、大小写错误。
6. **客户端注册状态是否卡住？**
   - 回首页点 **【修复连接】** 重置注册状态并重写配置。
7. **是否被安全软件拦截？**
   - 查安全软件日志，必要时加白名单后重试。

> 更细的现象 → 原因 → 解决对照表见 [`05-常见问题FAQ.md`](05-常见问题FAQ.md)。
