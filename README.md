## 一、这是什么

**RustDesk 一键配置助手** 是一个 RustDesk 的**外挂面板**（不是 RustDesk 的分支，也不实现任何远程控制功能）。

它只解决一件事：**把"让 RustDesk 在自建服务器上稳定跑起来"这件事，从十几次手工操作变成点几下按钮。**

- 它**不修改** RustDesk 的安装文件、**不替换**官方客户端；
- 它通过 RustDesk 官方支持的**配置文件**与**命令行参数**来生效；
- 它把 RustDesk 的**真实运行状态**（客户端进程是否在跑、有没有连上服务器、密钥有没有被确认）实时显示给你看。

技术形态：单文件 C# / WinForms 程序，用 Windows **自带**的 `csc.exe` 编译，产物体积约 **47 KB**，启动耗时约 **130~200 毫秒**。

## 二、为什么会有这个工具（背景）

作者家里的宽带被运营商（**联通**）**限制了上行 UDP 与 HTTPS(443) 流量**。这带来两个直接后果：

1. **RustDesk 官方服务器连不上** —— 需要用到被限制的流量形态；
2. **P2P 打洞打不通** —— 打洞严重依赖 UDP，上行 UDP 被封后几乎无法建立直连。

于是换了一条运营商**没有封的 TCP 通道**：

> 自建 **EasyTier** 去中心化组网，并配置为 **纯 TCP 中继**模式，把所有机器拉进同一个虚拟局域网；
> 再把 **RustDesk 服务端（hbbs / hbbr）部署在这个虚拟局域网内部**；
> 客户端把 **ID 服务器 / 中继服务器**都指向它。

网络这条线打通了，但**官方 RustDesk 客户端本身还有三个坑**，而这三个坑正是本工具诞生原因：

| # | 官方客户端的坑 | 后果 | 本工具的解法 |
|---|---|---|---|
| 1 | **不会开机自启动**，官方也没有可靠的设置入口 | 机器一重启，远程就断了，必须人工到现场打开 | 一键写入「登录后启动 / 开机即启动」两个计划任务，并实时回显是否已设置 |
| 2 | **没登录 Windows 桌面（还停在登录界面）时无法被远程** | 服务器重启后卡在登录界面，远程彻底失联 | 把 RustDesk 以**服务方式常驻**（`RustDesk` 服务负责与服务器保持连接），配合开机自启真正实现"开机即可远程" |
| 3 | **经常注册不上 / 状态卡住** | 面板上看着像在跑，其实根本没挂到 ID 服务器上 | 一键"修复连接"：重置注册状态 → 重写服务器配置 → 重启客户端 → 轮询校验是否真的注册成功 |

一句话总结：

> **EasyTier（或你的组网方案）负责"把网络打通"；RustDesk 一键配置助手负责"把 RustDesk 客户端伺候稳"。**

## 三、功能清单

### 1. 客户端进程 与 服务器连接，分开控制

很多人会被 RustDesk 的进程模型绕晕，本工具把它拆清楚：

| 名称 | 底层进程 | 结束后的行为 | 界面上的位置 |
|---|---|---|---|
| **客户端进程** | `rustdesk.exe --tray`（托盘/主界面进程） | **不会重生** | 「客户端进程 ● 运行中 / 未运行」+【启动】/【停止】 |
| **与服务器的连接** | Windows 服务 `RustDesk`（其子进程 `--server` 由服务自动拉起） | **立刻自动重生**，所以不能拿来当"客户端进程"判断依据 | 「与服务器连接 ● 已连接 / 未连接」+【连接】/【断开】 |

两者可以**分别启停**：想省资源可以只停客户端进程，服务器连接照常保持。

### 2. 开机自启动（含"是否已设置"的实时回显）

- **登录 Windows 后自动启动** —— 计划任务 `RustDeskHelper`
- **开机即启动（服务器，需管理员）** —— 计划任务 `RustDeskHelper-Boot`

每一项右侧都会实时显示：

- `✓ 已设置`（绿色）
- `✗ 未设置`（红色）

即使你在系统里手工改动计划任务，回到界面也会自动同步显示。

### 3. 服务器配置一键写入

把你在界面上填的服务器信息写进 RustDesk 的配置文件（`%APPDATA%\RustDesk\config\RustDesk.toml` 与 `RustDesk2.toml`）：

| 配置项 | 含义 |
|---|---|
| `custom-rendezvous-server` | ID 服务器地址（hbbs） |
| `relay-server` | 中继服务器地址（hbbr） |
| `key` | 服务器公钥，**必须**与服务端 `id_ed25519.pub` 完全一致 |
| `disable-udp` | 是否禁用 UDP（上行 UDP 被封时很有用） |
| `allow-websocket` | 是否允许 WebSocket 走 443（443 被封时建议关闭） |
| `enable-lan-discovery` | 局域网发现 |
| `direct-access-port` | 局域网直连端口（默认 21118） |

### 4. 固定密码（立即生效）

- 调用官方命令 `rustdesk.exe --password "xxx"` 写入客户端，**立即生效、无需重启**；
- 密码框默认以圆点掩码显示，点框内的**小眼睛**图标可临时查看明文；
- 一键**生成随机强密码**、一键**复制**。

> ⚠️ **重要**：固定密码**绝对不能**写进 `RustDesk.toml` 的 `[options]` 段——RustDesk 根本不识别这个字段，这正是网上"固定密码设置了却不生效"的元凶。本工具会自动**清理**这个无效配置项。

### 5. 一键修复连接

按正确顺序做完整套动作，并且**不删除任何系统目录**：

```
备份配置 → 重置 key_confirmed 注册状态 → 重写服务器配置 → 重启客户端 → 轮询校验注册结果
```

校验成功会提示：`✓ 修复完成：客户端已重新注册到 <服务器>`。

### 6. 实时状态刷新

后台线程每 **1.5 秒**轮询一次，界面**不卡顿**；面板**先显示、再异步刷新**，所以打开就是秒开。

### 7. 未安装 RustDesk 时自动下载安装最新版

打开工具时如果没检测到已安装的 RustDesk，会弹窗询问：

> 是否现在自动下载并安装当前最新版？

选择"是"之后：通过 GitHub API 取官方**最新版**的 `x86_64` 安装包 → 带进度窗口下载 → 以 `--silent-install` 提权**静默安装** → 最长轮询 4 分钟等待安装完成。

### 8. 全中文 · 单文件 · 秒开

- 界面、日志、提示**全中文**；
- **单文件** EXE，绿色免安装；
- 图标直接**复用本机 rustdesk.exe 的官方图标**，观感一致。


> 📌 本工具**不内置任何服务器地址**，三个字段默认都是空的——请填写**你自己**搭建的 RustDesk 服务端信息。

## 五、快速开始

> 前提：已经有一台**你自己搭建的 RustDesk 服务端（hbbs / hbbr）**，并且能从这台机器访问到它。
> 没有服务端？先看 [九、中继服务器](#九中继服务器easytier-纯-tcp-组网) 或 [八、局域网使用](#八局域网使用)。

1. **下载**：到本仓库的 **Releases** 页面下载最新的 `RustDesk 一键配置助手.exe`。
2. **运行**：**右键 → 以管理员身份运行**（写入计划任务、设置固定密码都需要管理员权限）。
   - 如果没装 RustDesk，工具会主动问你要不要自动安装最新版。
3. **填服务器**：切到【服务器设置】标签页，填上你自己的 **ID 服务器**、**中继服务器**（留空则与 ID 服务器相同）、**Key**（必须与服务端 `id_ed25519.pub` 完全一致），点【同步到客户端】。
4. **修复连接**：回到【连接状态】，点【修复连接】。工具会重置注册状态、重写配置、重启客户端。
5. **看状态**：底部状态行三段的颜色就是答案——
   - `服务器密钥：已确认（已注册）` **绿色** = 已经成功挂到你的服务器上 ✅
   - 还是**红色** = 继续看 [十一、常见问题](#十一常见问题)
6. **开机自启**：在【开机自启动】卡片勾选你需要的项，点【保存】。
7. **固定密码**（可选）：在【固定密码】卡片点【设置】，会自动生成一个强密码并写入客户端。

## 七、从源码编译打包成 EXE

**不需要 Visual Studio，也不需要 dotnet SDK**——只用 Windows 自带的 `csc.exe`。

```powershell
# 在仓库根目录执行
powershell -ExecutionPolicy Bypass -File src\build.ps1
```

产物输出到**仓库目录的上一级**：`RustDesk 一键配置助手.exe`（约 47 KB）。

编译脚本 `src/build.ps1` 做了这几件事：

1. **提取官方图标**：用 `LoadLibraryEx` + `EnumResourceNames` 直接从本机已安装的 `rustdesk.exe` 里**原样搬运** `RT_GROUP_ICON` / `RT_ICON` 资源，重建为标准 `.ico`，再通过 `/win32icon:` 传给编译器——所以图标和官方**逐字节一致**。
2. **在纯英文临时目录编译**：`csc.exe` 处理**中文路径**会出问题，所以脚本先把源码复制到 `%TEMP%\rdhelper_build`（纯英文字路径）再编译，最后把产物复制回中文目标路径。
3. **链接系统程序集**：`System.Windows.Forms`、`System.Drawing`、`System.Management`、`System.ServiceProcess`。

### 写这个项目时必须知道的几个坑

| 坑 | 说明 |
|---|---|
| **编译器只支持 C# 5** | `C:\Windows\Microsoft.NET\Framework64\v4.0.30319\csc.exe` 是老编译器，**不支持**字符串插值 `$""`、`?.`、元组、表达式体成员、`nameof`、`out var` 等新语法 |
| **源码必须是 UTF-8 with BOM** | 否则 csc 会把中文字面量编译成乱码 |
| **`build.ps1` 必须纯 ASCII** | PowerShell 5.1 会按 GBK 解码**无 BOM** 的 `.ps1`，脚本里有中文就会解析失败。脚本里的中文路径全部用 `[char]0xXXXX` 拼接 |
| **PowerShell 数组字面量的坑** | `@('/out:' + $path)` 会被拆成两个元素，要先算中间变量再包进 `@(...)` |

更详细的说明（含如何改图标、改作者信息、改默认服务器）见 **[docs/02-编译打包说明.md](docs/02-编译打包说明.md)**。

## 八、局域网使用

**场景一：纯局域网**（家里/公司同一网段）

- 在局域网里找一台常开的机器部署 RustDesk 服务端（hbbs / hbbr）；
- 其他机器在【服务器设置】里把 **ID 服务器**填成那台机器的局域网 IP（例如 `192.168.1.10`），**Key** 与服务端 `id_ed25519.pub` 保持一致；
- 局域网内可以直接直连，`direct-access-port`（默认 `21118`）会派上用场。

**场景二：EasyTier 虚拟局域网**（跨地区、跨运营商）——见 [第九节](#九中继服务器easytier-纯-tcp-组网)。

**端口清单**（自建服务端需要在防火墙放行）：

| 服务 | 端口 | 协议 |
|---|---|---|
| hbbs（ID/Rendezvous） | `21115` | TCP |
| hbbs（ID/Rendezvous） | `21116` | TCP **+ UDP** |
| hbbs（WebSocket，可选） | `21118` | TCP |
| hbbr（Relay 中继） | `21117` | TCP |
| hbbr（WebSocket，可选） | `21119` | TCP |

> 如果 **UDP 上行被运营商限制**，就把客户端的 `disable-udp` 设为 `N` 之外的值强制走 TCP，并让防火墙确保 TCP 的 `21115 / 21116 / 21117 / 21118` 全程打通。

完整操作步骤、`disable-udp` / `allow-websocket` / `enable-lan-discovery` 什么时候该开、失败排查顺序，见 **[docs/03-局域网使用说明.md](docs/03-局域网使用说明.md)**。

## 九、中继服务器（EasyTier 纯 TCP 组网）

这是本工具诞生的网络前提，也是作者实际在用的方案：

```
   运营商限制：上行 UDP ✗    443/TCP(HTTPS) ✗
                │
                │  只能走「没被封的 TCP 端口」
                ▼
   ┌──────────────────────────────────────────────┐
   │   EasyTier 去中心化组网（纯 TCP 中继模式）        │
   │                                              │
   │   节点 A          节点 B          节点 C        │
   │  10.0.0.2       10.0.0.3       10.0.0.4      │
   │       \             │             /          │
   │        \            │            /           │
   │         └────── 虚拟局域网 ──────┘             │
   │                    │                         │
   │              10.0.0.1（服务端节点）             │
   │        ┌───────────┴───────────┐             │
   │        │  hbbs(21115/21116)     │             │
   │        │  hbbr(21117/21119)     │             │
   │        └───────────────────────┘             │
   └──────────────────────────────────────────────┘
                │
                │  每台机器用本工具把 ID服务器/中继服务器
                ▼  指向 10.0.0.1，并写入同一个 Key
       RustDesk 客户端 ──► 稳定注册成功、可被远程
```

**为什么这么绕？** 因为直接连官方服务器要仰仗被限制的流量形态，而"自建 TCP 中继 + 虚网内自建服务端"这条路**完全绕开了 UDP 与 443**。

> 上图中的网段与地址均为**示例占位值**，请按你自己的实际规划填写。

关于 EasyTier 的组网思路、纯 TCP 中继的配置要点、虚拟 IP 规划、连通性验证方法、以及"免登录桌面即可远程"的配合方式，见 **[docs/04-EasyTier纯TCP中继服务器说明.md](docs/04-EasyTier纯TCP中继服务器说明.md)**。

> 🔐 **安全提示**：服务器 **Key** 属于敏感信息，请勿提交到公开仓库；虚拟网段与真实 IP 也不建议公开。

## 十一、常见问题

| 现象 | 一句话原因 |
|---|---|
| 点【停止】后再点【启动】没反应 / 状态不刷新 | 后台每 1.5 秒轮询，稍等一下；若仍不动请看日志 |
| 固定密码设置了却连不上 | 密码**不能**写进 `[options]` 段，本工具已自动清理该无效项 |
| 客户端状态一直显示"运行中" | 把服务自动拉起的 `--server` 子进程误判成了客户端进程（本工具已用命令行参数过滤） |
| 开机自启动显示"未设置"或设置后不生效 | 需要**管理员权限**写入计划任务 |
| "服务器密钥"一直红色未确认 | Key 与 `id_ed25519.pub` 不一致 / 服务器地址不通 / 防火墙没放行 |
| 停在 Windows 登录界面无法被远程 | 需要让 RustDesk 以**服务方式常驻**，配合开机自启 |
| 杀毒软件报毒 | 未签名程序 + 联网下载执行，属**误报**，加白名单即可 |
| 日志在哪看 | 界面【查看日志】，文件在 `%LOCALAPPDATA%\RustDeskHelper\helper.log` |

完整版（每条含"现象 → 原因 → 解决"三步）见 **[docs/05-常见问题FAQ.md](docs/05-常见问题FAQ.md)**。
